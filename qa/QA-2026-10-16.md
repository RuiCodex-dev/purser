## 3. Defects found and fixed (commits on `main`, all tagged RUI-219)

| # | Defect | Fix |
| --- | --- | --- |
| 1 | Two identical payouts/refunds at the same time could both pass the mandate (evaluated before either was recorded) -> double payment | Money moves serialised per event; the mandate is evaluated under the lock |
| 2 | Card declined at capture (`INSTRUMENT_DECLINED`) left the payer stuck: order stayed APPROVED, Pay did nothing, reconcile retried the capture forever | Payer is sent back to PayPal's approval page for the same order; reconcile waits; a fresh approval clears the decline |
| 3 | A payer approving an older, superseded request (amount changed after a drop-out) would have been captured at the old amount | A superseded approval is never captured; the payer is told and asked for the current amount |
| 4 | Network error / timeout from PayPal threw out of the executor (HTTP 500, no audit) | Recorded as a failed call in the audit, nothing applied to the ledger; 30 s timeouts |
| 5 | An expired or revoked OAuth token was never refreshed before its local expiry | One refresh + retry with the same PayPal-Request-Id |
| 6 | Live PayPal errors hid the issue code (`details[].issue`), so the decline handling could never trigger in live mode | `describeError` keeps the issue codes |
| 7 | Gemini (3.5 Flash) sometimes glued junk into a vendor name ("Lakeside Rentals shelterEmail ...", "Lakeside Rentals假装,") or dropped a vendor email -> brief rejected, or a payout addressed to a placeholder email | Grounded repair (cut back only to text in the brief, only when the value shows leaked structure), cross-fill with the strict parser, restore an email written in the vendor's own sentence; invented names still fail |
| 8 | Ledger grid: "square" label in Position, truncated amounts/states, horizontal scroll that hid the Person column after a sort at 1600 px | `$0.00`, tighter columns and padding, short state labels |
| 9 | Model label read "Gemini 3.5-flash" | "Gemini 3.5 Flash" |
| 10 | `mathjs` advisory in the toolkit's runtime path | npm override to 15.2.0 |
| 11 | **Found live (section 10).** A drop-out refund was sent twice. PayPal answers a refund with id, status and links only; Purser read `amount.value` from that answer, threw, and booked the call as "could not reach PayPal, nothing was recorded"; the agent retried, and the toolkit's `create_refund` carries no PayPal-Request-Id, so PayPal refunded again | The amount booked is the explicit amount sent; before every refund Purser reads the capture's refunds from PayPal, books any it did not know about and sends nothing more. The offline fixture now answers like the live API. Regression test: a refund whose answer is lost is booked once from PayPal and never sent twice (fails on the old code) |
| 12 | **Found live (section 10).** Gemini (3.5 Flash Lite fallback) marked every cost non-refundable although the brief says only the cabin is, so a drop-out would have been refunded nothing | Refundability is grounded in the brief: a cost is non-refundable exactly when a sentence about it says so; a cost the brief never mentions keeps the model's value. Test in both directions |
